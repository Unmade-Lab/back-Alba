# Полное руководство Frontend-разработчика (AI CRM API)

Это руководство создано специально для интеграции Frontend-части с нашим AI-бэкендом. Архитектура построена на комбинации REST API (запросы/действия) и WebSockets (асинхронный стриминг ответов).

---

## 1. Авторизация и Изоляция данных (SaaS)
Все защищенные запросы (к чату, сессиям, экшенам) **обязательно** требуют HTTP-заголовок с токеном.
*Header:* `Authorization: Bearer <token>`

Наш бэкенд работает в мульти-тенантном (SaaS) режиме. Зашитый в токен `workspace_id` гарантирует строгую изоляцию данных: каждый сотрудник получает доступ **только** к сделкам, клиентам и истории чатов своей собственной компании. Доступ ко всем `api/v1/*` (кроме открытых `/auth/*`) без выданного JWT-токена будет отклонен (401 Unauthorized).

---

## 2. Идеальный сценарий (Жизненный цикл переписки)

Вот как должно работать приложение на фронтенде шаг за шагом:

1. **Загрузка Сайта:** Фронтенд делает `GET /api/v1/chat/sessions`, получает массив чатов и отрисовывает левое меню.
2. **Новый чат:** Пользователь жмет "Новый чат". Фронтенд локально генерирует свежий UUID (например `const sessionId = uuidv4()`), открывает пустой экран и подключает WebSocket к этому ID.
3. **Общение:** Пользователь пишет сообщение "Создай компанию Apple". Фронтенд отправляет его через `POST /api/v1/chat/message`.
4. **Стриминг:** Бэкенд по WebSocket начинает присылать куски текста (эффект печати) с типами `stream_start`, затем много `stream_chunk`.
5. **Отрисовка виджета:** Вместе с последним сообщением (тип `message` в WS или в ответе на `POST`) приходит поле `widget`. Фронт рендерит красивую форму для создания компании Apple.
6. **Сохранение:** Пользователь заполняет поля в виджете-форме и жмет кнопку "Сохранить/Подтвердить". Фронтенд отправляет эти данные через `POST /api/v1/commands/commit`. Форма скрывается/блокируется. Сюрприз — компания создана в PostgreSQL!

## 3. Справочник REST API

### 3.1. Регистрация бизнеса (Первый старт)
Для создания новой компании (пустого изолированного пространства).
**Запрос:** `POST /api/v1/auth/register` (Не требует Auth)
```json
{
  "workspace_name": "ООО Ромашка",
  "user_name": "Иван Д.",
  "email": "owner@example.com",
  "password": "secret123"
}
```
**Ответ (201 Created):** Возвращает JWT токен, `user` (с ролью admin) и `workspace`.

### 3.2. Логин (Авторизация)
Принимает учетные данные и возвращает JWT-токен на 24 часа. Используйте его в заголовке `Authorization: Bearer <token>` для **всех** защищенных маршрутов!
Если вы разворачиваете чистую БД без регистрации из пункта 3.1, дефолтный админ: `admin@alba.local` / `admin123`.

**Запрос:** `POST /api/v1/auth/login` (Не требует Auth)
```json
{
  "email": "owner@example.com",
  "password": "secret123"
}
```
**Ответ (200 OK):**
```json
{
  "token": "eyJhb...",
  "user": {
    "id": "00000000-...",
    "name": "Иван Д.",
    "email": "owner@example.com",
    "role": "admin",
    "workspace_id": "uuid..."
  }
}
```

### 3.3. Активация инвайта сотрудника
Когда администратор через ИИ добавляет нового сотрудника, ИИ выдаст ссылку вида `https://.../invite?token=ABC`. 
Новый сотрудник переходит по ссылке, придумывает пароль, и фронтенд кидает этот запрос для активации:

**Запрос:** `POST /api/v1/auth/activate` (Не требует Authorization заголовка)
```json
{
  "token": "ABC",
  "password": "my-secret-password"
}
```
**Ответ (200 OK):**
```json
{
  "message": "Account created and activated successfully",
  "email": "ivan@example.com",
  "role": "engineer"
}
```

### 3.4. Получение списка чатов (Список сессий)
Получение истории тем (показывается в Sidebar). Обязательно добавьте заголовок `Authorization: Bearer <token>`.

**Запрос:** `GET /api/v1/chat/sessions`
**Ответ (200 OK):**
```json
{
  "count": 1,
  "sessions": [
    {
      "id": "1f8e612f-923f-4e00...",
      "user_id": "00000000-0000...",
      "title": "Создание компании Apple",
      "created_at": "2026-04-05T22:30:10Z",
      "updated_at": "2026-04-05T22:33:13Z"
    }
  ]
}
```

### 3.5. Получение истории конкретного чата
Загрузка истории переписки (при клике на чат в боковом меню). Не забудьте `Authorization: Bearer <token>`.

**Запрос:** `GET /api/v1/chat/history?session_id=<UUID>&limit=50`
**Ответ (200 OK):** Возвращает массив объектов сообщений (с текстами и виджетами) от старых к новым.

### 3.6. Отправка сообщения
Основной метод диалога с ИИ ассистентом. Бэкенд заблокирует запрос на 2-10 секунд, пока ИИ думает (хотя в WebSocket текст начнет литься почти сразу).

**Запрос:** `POST /api/v1/chat/message`
```json
{
  "session_id": "<UUID сессии>",
  "message": "Создай сделку с клиентом Tesla на 500 долларов"
}
```
**Ответ (200 OK):** Возвращает итоговый объект сообщения (тот же, что и прилетает финальным в WS).
```json
{
  "type": "message",
  "message_id": "f758808f-...",
  "session_id": "...",
  "text": "Создаю карточку для сделки...",
  "widget": {
     "type": "form",
     "title": "Новая сделка",
     "fields": [ ... ]
  },
  "created_at": "2026-04-05T23:00:00Z"
}
```

### 3.7. Confirm / Commit (Интерактивные черновики)
Когда пользователь подтверждает действия на виджите, результат данных отправляется сюда.

**Запрос:** `POST /api/v1/commands/commit`
```json
{
  "session_id": "<UUID чата, в котором был виджет>",
  "action_name": "create_deal",
  "payload": {
     "deal": {
       "name": "Tesla Deal",
       "amount": 500,
       "stage": "new"
     }
  }
}
```

## 4. WebSockets (Потоковый вывод / Streaming)

Вебсокет используется **только для получения** ответа (эффекта печати). 

**Подключение:** `ws://localhost:8080/ws/chat?session_id=<UUID>`

**Пример обработки на JavaScript (React/Vue/Vanilla):**
```javascript
const ws = new WebSocket(`ws://localhost:8080/ws/chat?session_id=${currentSessionId}`);

ws.onmessage = (event) => {
    const data = JSON.parse(event.data);
    
    switch (data.type) {
        case "stream_start":
            // 1. Создаем пустой пузырь сообщения на экране 
            // с id = data.message_id и показываем "печатает..."
            console.log("ИИ начал печатать сообщение: ", data.message_id);
            break;

        case "stream_chunk":
            // 2. Ищем на экране сообщение с data.message_id 
            // и прибавляем data.text в конец!
            console.log("Частица текста:", data.text);
            break;

        case "message":
            // 3. Сообщение готово! Заменяем весь текст на data.text (для надежности).
            // Если есть data.widget !== null, рисуем под текстом Форму/Виджет!
            console.log("Собираем виджет: ", data.widget);
            break;
    }
};
```
